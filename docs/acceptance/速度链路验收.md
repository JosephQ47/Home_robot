- 日期：2026-09-18
- 环境：Ubuntu 22.04 / ROS 2 Humble / PC（非实机）
- 被测：`hr_motion_mux` + `nav2_collision_monitor`（真实停止区 + 真实 `/scan`）
- 判据来源：技术方案 §10.3「速度单通道 / 碰撞停止区」

这是整个项目最核心的不变量：**无论还跑着什么，`/cmd_vel_auto` 和 `/cmd_vel`
都必须各自恰好只有一个发布者**，且 Nav2 与 Docking 除了经由它们之外无法触及底盘。

```text
collision_monitor lifecycle state: active [3]

=== AC-C1  exactly one publisher on each chain topic ===
  /cmd_vel_auto   publishers=['hr_motion_mux']  expect [hr_motion_mux]  -> PASS
  /cmd_vel        publishers=['collision_monitor']  expect [collision_monitor]  -> PASS
=== AC-C2  NAVIGATING: nav passes, dock is blocked ===
  nav 0.20  -> /cmd_vel_auto peak=0.20 (expect 0.20)
  dock 0.20 -> /cmd_vel_auto peak=0.00 (expect 0.00)
=== AC-C3  DOCKING: dock passes, nav is blocked ===
  dock 0.08 -> /cmd_vel_auto peak=0.08 (expect 0.08)
  nav 0.20  -> /cmd_vel_auto peak=0.00 (expect 0.00)
=== AC-C4  clear scan: Collision Monitor forwards to /cmd_vel ===
  /cmd_vel_auto peak=0.15   /cmd_vel peak=0.15 (expect 0.15)
  /cmd_vel messages=97 (expect > 0)
=== AC-C5  obstacle inside the stop zone: the veto fires ===
  /cmd_vel_auto peak=0.15 (mux still forwards; that is its job)
  /cmd_vel      peak=0.00 (expect 0.00)
=== AC-C6  obstacle cleared: motion resumes ===
  /cmd_vel peak=0.15 (expect 0.15)
=== AC-C7  every chain message has linear.y == 0 ===
  non-zero linear.y = 0 of 486 (expect 0)
```

## 本次配置修正：停止区多边形的格式

仓库原来的 `collision_monitor.yaml` 把 `points` 写成字符串 `"[]"`：

```yaml
points: "[]"      # 旧写法
```

本机 nav2 版本把该参数定型为 **double 数组**，字符串形式在 configure 阶段直接报
`Wrong parameter type ... setting it to {string} is not allowed`，节点停在
`unconfigured` 再也起不来。旧文档里常见的 `"[[x, y], ...]"` 写法同样会被拒。

改为扁平数组，并给了一个**明显保守的占位矩形**而不是空多边形：

```yaml
points: [0.50, 0.30, 0.50, -0.30, 0.0, -0.30, 0.0, 0.30]
```

为什么不继续留空：空多边形会让节点 configure 失败，于是它**根本不出现在 ROS graph
里**——拓扑检查会看到「没有 Collision Monitor」，却分不清是「还没接」还是「接了但挂了」。
一个起得来、明确标注 PENDING FREEZE 的保守矩形，比一个悄悄缺席的节点诚实。

冻结它仍需四个实测数字（技术方案 §10.4）：机器人轮廓、扫描到轮子的总延迟、
实测制动距离、安全余量。在那之前 `enable_real_navigation` 保持默认关闭。

已验证修改后的仓库配置可以 configure + activate 到 `active [3]`。
