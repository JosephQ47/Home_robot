## 这次验的是什么，不是什么

**是真实代码路径**：抓取状态机、全部安全互锁、六轴逆运动学、关节轨迹下发、
mock 舵机控制器的收敛、夹持确认（LIFT_VERIFY）、失败时的停止指令与阶段记录。

**被绕过的**：`hr_arm_perception` 节点未启动，因为本机没有安装 `vision_msgs`。
验证脚本直接发布 `/arm/grasp_candidates` 顶替它。该节点自身的门控逻辑
（标定有效性、深度密度/一致性、夹爪开口）有 28 条单元测试单独覆盖。

**完全没有验的**：真实机械臂、真实舵机控制器、真实 D435i、真实手眼标定。
连杆长度用的是配置里的占位值，装车前必须实测替换。

## 本次修掉的一个 fail-open

`hr_arm_controller` 原本从 `/robot_status` 读轮速来判断底盘是否停稳，写法是
`getattr(msg, 'wheel_vx', 0.0)`。但 `RobotStatus.msg` 里**根本没有轮速字段**——
于是「取不到数据」被 0.0 兜底成了「速度为零」，ARM-1 的四重确认里这一重恒为真。

这是项目明令禁止的失效方向：读不到数据绝不能当成安全。
改为订阅真正携带轮速的 `/wheel/odom_raw`，并加 `odom_timeout_ms` 新鲜度检查——
里程计过期或缺失时主动**撤销**「已停稳」这个确认，而不是保留上一次的结论。

同类修正：安全故障判据由单看 `safety_permit` 扩展为
`safety_permit / control_source==SAFE_STOP / fault_code!=0 / watchdog_healthy`
四者任一成立即视为故障。

## 另一个被往返测试抓出的缺陷

六轴逆运动学最初把肩角与肘角的符号配对写反了（`j3` 为正时肩角应取 `beta - alpha`，
原写成 `beta + alpha`）。这个错误不会抛异常、不会越限，只会返回一个**镜像了的姿态**——
看起来完全合理，装到真机上就是抓空。

是「用正运动学生成位姿，再让逆运动学还原」的往返测试把它抓出来的。
修复后往返误差在 1e-16 量级。
