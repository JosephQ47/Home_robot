# 语音链路运行时验收证据

- 日期：2026-09-18
- 环境：Ubuntu 22.04 / ROS 2 Humble / PC（无麦克风）
- 被测：`hr_voice_capture`（asr_adapter=text，wake_word=小家，窗口 8 s）
- 判据来源：`docs/features/hr_voice.md` §5

```text
=== AC-V1  no wake word -> nothing forwarded ===
  "去客厅" before wake -> [] (expect [])
=== AC-V2  wake word itself is not a command ===
  "小家" -> [] (expect [])
=== AC-V3  command inside the window is forwarded with its confidence ===
  "去客厅|0.93" -> ['去客厅|0.93'] (expect ["去客厅|0.93"])
=== AC-V4  one wake word yields one command ===
  "去厨房" right after -> [] (expect [])
=== AC-V5  window expires ===
  "去客厅" after 8.5 s -> [] (expect [])
=== AC-V6  malformed confidence is not rounded up ===
  "去客厅|很确定" -> ['去客厅|很确定|0.0'] (expect confidence 0.0)
```

## 这次验的是什么

唤醒门的全部行为：唤醒前一律不放行；唤醒词本身不当作命令；
一次唤醒只放行一条命令（防止一句唤醒引出一串误触发）；窗口到期后自动关闭；
置信度解析失败时取 0.0 而不是 1.0。

最后一条值得单独说：解析失败取 1.0 会让一句听错的话以「完全确信」的身份进入
意图映射，而 `hr_voice_command` 的低置信度拒绝正是最后一道防线。
失败的方向必须是拒绝，不是放行。

## 被绕过的

真实麦克风与 ASR 引擎。`asr_adapter=text` 从 `/voice/text_in` 读入文本顶替识别结果，
这也是 PC 上演示整条语音链的方式：

```bash
ros2 topic pub --once /voice/text_in std_msgs/String "data: '小家'"
ros2 topic pub --once /voice/text_in std_msgs/String "data: '去客厅|0.93'"
```

Vosk 适配器已写好但未运行——它需要模型文件，而麦克风尚未选型。
