## 二、`hr_dock_pose_adapter`

```text
=== AC-D1  one sighting is not enough (needs 3 consecutive) ===
  poses after 1 sighting = 0 (expect 0)
=== AC-D2  three consecutive sightings publish the contact pose ===
  pose=(1.3000, 0.0000) frame=odom expect (1.30, 0.00) odom   [tag at 1.0 + 0.30 contact offset]
=== AC-D3  wrong tag id is refused ===
  poses = 0 (expect 0)
=== AC-D4  low decision margin is refused ===
  poses = 0 (expect 0)
=== AC-D5  nonzero hamming is refused ===
  poses = 0 (expect 0)
=== AC-D6  invalid CameraInfo is refused ===
  poses = 0 (expect 0)
=== AC-D7  pose jump beyond the gate is refused ===
  poses after the jump = 0 (expect 0)
=== AC-D8  TF unavailable -> no pose, never a stale one ===
  poses = 0 (expect 0)
```

AC-D2 的 `(1.3000, 0.0000)` = Tag 在 1.0 m 处 + 0.30 m 的 Tag—触点偏置，与冻结配置一致。

## 本轮修掉的两个缺陷

**1. `apriltag_msgs` 根本不含位姿。**
`AprilTagDetection` 只有 `family / id / hamming / decision_margin / centre /
corners / homography`——全是像素几何。`apriltag_ros` 是通过 **TF** 发布 Tag 三维位姿的。
原实现假设了 `detection.pose.pose.pose`，这个字段不存在，一运行就抛异常。

改为：**检测数组决定「这个 Tag 可不可信」（ID、family、hamming、decision_margin），
TF 决定「它在哪」**。这也顺带把像素级门控和几何门控分开了，前者不需要等 TF。

**2. TF 缓存导致的 fail-open。**
改用 TF 之后，AC-D8 立刻暴露了新问题：`tf2` 的 Buffer 会按缓存时长保留变换，
用「最新可用」（`rclpy.time.Time()`）去查，**广播停止之后仍然返回上一帧**。
于是相机已经看不见 Tag 了，节点还在发位姿——正是 DOCK-2 要禁止的事。

修法是校验变换自身的 `header.stamp` 年龄，超过 `tag_timeout_ms` 即拒绝。
「查不到」和「查到的是旧的」必须都算失败。

**3. `vision_msgs` 的字段是嵌套的。**
`bbox.center` 是 `Pose2D`，要走 `.position.x`；`results[i]` 要走
`.hypothesis.class_id` 与 `.hypothesis.score`。已与仓库里既有的
`hr_target_tracker` 写法对齐。
