- 环境：Ubuntu 22.04 / ROS 2 Humble / PC
- 被测：`hr_voice_capture` → `hr_voice_command` → `hr_task_manager` → Nav2 → `hr_arm_controller` → `hr_arm_driver`
- 判据来源：技术方案 §3.12.2、§3.12.5

一句「小家」唤醒，一句「抓取杯子」，走完
`PRECHECK → NAVIGATING → ZERO → DONE` 的完整业务链：派发、准入、
导航到工作位、停稳确认、抓取序列、放置、回零。

## 关键设计点

**导航段与机械臂段严格不重叠。** 阶段只在前往工作位这一段是 `NAVIGATING`，
一旦到位立刻回到 `ZERO`。AC-E3 验的就是这个：最后一个 `NAVIGATING` 之后
发布的每一条阶段都是 `ZERO`，不存在轮子和机械臂同时被授权的窗口。

**底盘全程锁在 ZERO。** 机械臂任务期间 `hr_motion_mux` 拒绝一切自动速度源。
「机械臂动作时底盘不许动」由速度链强制执行，而不是靠每个节点各自记得。

**`ARM_STOP` 不排队。** 一个需要排在它要停的东西后面的停止不是停止。
准入规则里它是唯一可以在任务运行中被受理的类型，且不占用 active 槽位。

## 本轮修掉的三个缺陷

**1. 多线程执行器缺回调组。** `hr_task_manager` 早就用了 `MultiThreadedExecutor`，
但从未给任何回调指定 `ReentrantCallbackGroup` —— 所有回调仍落在默认互斥组里，
额外线程一个也用不上。`execute()` 为长任务阻塞时 `/robot_status` 进不来，
任务把自己中断成 `SAFETY_INVALID`。这正是 CLAUDE.md 那条
「不许在回调里阻塞，需要并发就上 MultiThreadedExecutor + ReentrantCallbackGroup」——
只有前者是没有用的。

**2. 放置点落在工作空间之外。** 换上真实连杆长度（肩部臂展 0.275 m）后，
配置里的放置点 `[0.20, -0.15, 0.10]` 距肩部 0.255 m 尚可，但加上抬升高度就越界，
抓完放不下。IK 拒绝得对，是配置错了。新增 `test_workspace.py` 直接读取
安装后的 yaml，断言放置点、抓取包络都在连杆长度推出的可达范围内 ——
这两组参数本来就可能互相矛盾，现在矛盾会在测试里暴露而不是在真机上。

**3. `docks.yaml` 让 rcl 拒绝整个文件。** 顶层除 `ros__parameters` 外还有一个
`docks:` 段，参数解析器直接报 `Cannot have a value before ros__parameters`，
节点根本起不来。已拆出 `dock_database.yaml`：前者是纯参数文件，后者是任务层
读取的桩位数据库。抓 ROS 计算图时才发现 —— 这个节点此前从未被真正启动过。
